## 2. Sample Schema

每条 Canonical Sample 必须包含：

```text
id
source
split
task
language
input
output
annotations
meta
```

顶层字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一的 Canonical 样本 ID |
| `source` | string | 原始数据集名称 |
| `split` | `train` / `validation` / `test` | 统一后的数据划分 |
| `task` | string | 任务类型 |
| `language` | string | 样本主要语言 |
| `input` | object | 模型输入 |
| `output` | object | 模型目标与参考答案 |
| `annotations` | object | 训练监督、评测信息和原始字段 |
| `meta` | object | 追踪、分组、原始 split 和转换信息 |

稳定结构使用 `additionalProperties: false`，防止未经确认的字段进入 Canonical 数据。

### 2.1 Input

`input` 必须包含：

```text
images
context
prompt
history
```

- `context`：正文、长文档或序列化表格；没有时使用空字符串。
- `prompt`：当前问题、指令或摘要要求。
- `history`：当前问题之前的对话消息；单轮任务使用空数组。
- `images`：图片资源数组；没有图片时使用空数组。

每条 history message 必须包含 `role` 和 `content`：

```json
{
  "role": "user",
  "content": "..."
}
```

`role` 只允许 `user` 和 `assistant`。

### 2.2 图片资源

图片资源通过 `oneOf` 区分三种存储方式。

普通文件：

```json
{
  "storage": "file",
  "path": "media/docvqa/page001.png"
}
```

ZIP 内图片：

```json
{
  "storage": "zip",
  "path": "datasets/MMTab/images.zip",
  "member": "IID_train_image/table001.jpg"
}
```

Parquet 内嵌图片：

```json
{
  "storage": "parquet",
  "path": "datasets/DocVQA/train-00000-of-00012.parquet",
  "row": 123,
  "field": "image"
}
```

其中：

- `file` 必须有 `storage`、`path`；
- `zip` 必须有 `storage`、`path`、`member`；
- `parquet` 必须有 `storage`、`path`、`row`、`field`。

### 2.3 Output

`output` 必须包含：

```text
text
format
references
```

`text` 始终为字符串，是 SFT 的标准目标文本。 `format` 只允许：

```text
text | number | json | html
```

建议映射：

- 普通答案、摘要：`text`；
- 数值答案：`number`；
- JSON 抽取结果或答案数组：`json`；
- 表格重建结果：`html`。

`references` 必须是字符串数组，用于保存等价正确答案。原始答案类型、scale、program、derivation 等不能只依赖 `text` 推断，应保存在 `annotations` 中。

### 2.4 Annotations

`annotations` 必须包含三个 object：

```text
supervision
evaluation
raw
```

三个内部允许数据集自定义字段：

| 命名空间 | 用途 | 典型字段 |
|---|---|---|
| `supervision` | 可用于额外训练的监督 | FinQA program/steps、XFUND entities/relations/OCR/layout |
| `evaluation` | 官方评测需要的样本属性 | answer_type、scale、answer_from、answer_list |
| `raw` | 必须保留但尚未统一语义的源字段 | 原始 conversation、源数据集特有字段 |

评测器、指标和规则属于 Dataset Config，不应重复写入每条 Sample；但 reference、program、scale、derivation 等样本级属性必须保留。

### 2.5 Meta

`meta` 必须包含：

```text
source_id
group_id
subset
original_split
transforms
```

`transforms` 为字符串数组。推荐的 `group_id` 粒度：

| 数据集 | 推荐 group |
|---|---|
| DocVQA | document/page |
| MMTab | 原始 table image |
| FinQA | report/page |
| TAT-QA | report/table context |
| XFUND | document/form |
| GovReport | report |

同一文档、表格或图片产生的多个问题应共享 `group_id`，用于去重和防止跨 split 泄漏。

## 3. Dataset Config

每个数据集配置必须包含：

```text
schema_version
dataset
conversion
source_files
split_aliases
evaluation
files
```

### 3.1 数据集和转换信息

```yaml
schema_version: "1.0"
dataset:
  name: FinQA
  version: local_snapshot
  languages:
    - en
conversion:
  converter: finqa
  version: "1.0"
```

`dataset.languages` 必须是字符串数组。原始数据没有明确发布版本时使用 `local_snapshot`，不得伪造版本号。

### 3.2 原始文件和 split 别名

`source_files` 的 `train`、`validation`、`test` 如果存在，必须是字符串数组：

```yaml
source_files:
  train:
    - datasets/FinQA/dataset/train.json
  validation:
    - datasets/FinQA/dataset/dev.json
  test:
    - datasets/FinQA/dataset/test.json
```

多 shard、多语言和多来源数据使用同一数组，不使用 glob 替代真实文件清单。

`split_aliases` 是字符串到字符串的映射：

```yaml
split_aliases:
  train: train
  dev: validation
  test: test
```

例如 XFUND 的原始 `val` 文件实际对应官方 test，可以写成 `val: test`。

### 3.3 评测和 Canonical 文件

```yaml
evaluation:
  evaluator: finqa
  metrics:
    - execution_accuracy
    - program_accuracy
  rules:
    evaluate_program: true

files:
  train:
    - processed/finqa/train.jsonl
  validation:
    - processed/finqa/validation.jsonl
  test:
    - processed/finqa/test.jsonl
```

`metrics` 必须为字符串数组，`rules` 为 object，允许不同 evaluator 定义自己的评测规则。 `files` 中的 split 文件如果存在，也必须使用字符串数组。

## 4. 六类数据集映射

| 数据集 | Input | Output | 关键监督/评测信息 |
|---|---|---|---|
| DocVQA | 页面图片 + question | 文本答案 | 多 reference、Parquet row/field、document/page |
| MMTab | 表格图片 + instruction + history | text/JSON/HTML | conversation、subset、task_type、answer_list |
| FinQA | 财报正文 + table + question | 数值或文本答案 | program、steps、gold evidence、table/text rows |
| TAT-QA | table + paragraphs + question | span、multi-span 或数值 | answer_type、answer_from、scale、derivation |
| XFUND | 表单图片 + 抽取指令 | JSON | entity label、bbox、words、linking、多语言 |
| GovReport | 长报告 source + summary 指令 | 摘要文本 | 长 context、source/target、ROUGE |

## 5. 校验要求

所有 Canonical JSONL 和 Dataset Config 使用：

```python
from jsonschema import Draft202012Validator
```

校验顺序：

1. 对 JSON Schema 执行 `Draft202012Validator.check_schema`；
2. 逐条校验 Sample JSONL；
3. 用 YAML 解析 Dataset Config，再逐份校验；
4. 保留失败文件、行号、JSON Path 和错误原因；
5. 定期运行负向测试，确保 Schema 不会静默接受非法数据。

当前已验证的负向用例包括：非法 split、非法 output format、缺少 prompt、缺少 ZIP member、缺少 Parquet row、非法 history role，以及 `files` 使用 scalar。

## 6. 冻结结论

当前 Canonical Schema v1.0 已通过六类真实数据集验证，并通过 Draft 2020-12 程序化校验：

- 合法 Sample：18/18 PASS；
- 合法 Dataset Config：6/6 PASS；
- 非法样本：7/7 FAIL；
- 原始数据集和示例 Schema 文件均未修改。

因此：

> **Canonical Schema v1.0 可以冻结。**

后续新的多模态消息类型或结构化 table 原生字段，应作为 v1.1 兼容扩展评估，不直接改变 v1.0 的字段语义。
