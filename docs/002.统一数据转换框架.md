# M1：统一数据转换框架

## 1. M1 做了什么

实现最小可用的统一转换链路：

```text
Raw DocVQA
→ Dataset Config
→ DocVQA Converter
→ Canonical Sample
→ JSON Schema Validator
→ JSONL Writer
→ Statistics
```

本阶段只接入 DocVQA，不包含训练、采样、去重、表格渲染或其他数据集转换逻辑。正式 Schema 未修改：

- `assets/sample.schema.json`
- `assets/dataset_config.schema.json`

转换结果自包含于 `processed/docvqa/`：图片从 Parquet 中提取到 `media/`，同一图片按内容哈希只保存一次，JSONL 仅引用 `media/...` 相对路径。

## 2. 目录结构

```text
src/
├── core/
│   ├── config.py       # YAML 配置、变量展开和 Config Schema 校验
│   ├── converter.py    # Converter 最小抽象接口
│   ├── validator.py    # Sample/Config/图片资源校验
│   ├── writer.py       # 流式 JSONL 写入
│   └── stats.py        # 基础统计
├── converters/
│   └── docvqa.py       # DocVQA Parquet 流式转换和媒体落盘
└── convert.py          # 统一 CLI 入口

configs/datasets/docvqa.yaml
processed/docvqa/
├── train.jsonl
├── validation.jsonl
├── test.jsonl
├── stats.json
└── media/
```

## 3. 核心组件职责

- `core/config.py`：读取 YAML，展开 `${PROJECT_ROOT}`、`${DATASETS_ROOT}`、`${PROCESSED_ROOT}`，并使用 `dataset_config.schema.json` 校验。
- `core/converter.py`：定义 `load_split`、`convert_sample`、`iter_samples` 三个最小接口。
- `converters/docvqa.py`：流式读取 Parquet；将内嵌图片写入 `processed/docvqa/media/`；按内容哈希去重。
- `core/validator.py`：使用 `jsonschema.Draft202012Validator` 校验 Config、Canonical Sample 和图片资源存在性。
- `core/writer.py`：UTF-8 流式 JSONL 写入，按 split 输出。
- `core/stats.py`：统计样本、split、task、language、图片引用和文本长度；`output_chars` 仅统计 supervised 样本。

配置中的路径通过统一变量获得，默认值为：

```text
PROJECT_ROOT  = 当前项目根目录
DATASETS_ROOT = PROJECT_ROOT 的同级 datasets/
PROCESSED_ROOT = PROJECT_ROOT/processed
```

也可以通过同名环境变量覆盖。当前正式配置在 `source_files` 和 `files` 中使用这些变量，没有硬编码机器绝对路径。

## 4. DocVQA 字段映射

| 原始字段 | Canonical 字段 |
|---|---|
| `question` | `input.prompt` |
| 无上下文 | `input.context = ""` |
| Parquet 内嵌 image | `input.images[0] = {storage: file, path: media/...}` |
| `answers` | `output.references` |
| 第一个 reference | `output.text` |
| 固定文本答案 | `output.format = text` |
| `question_types` | `annotations.supervision.question_types` |
| 原始答案、答案数量 | `annotations.evaluation` |
| `docId`、UCSF document/page、原始 image path | `annotations.raw` |
| 原始 question ID | `meta.source_id` |
| document/page | `meta.group_id` |
| 原始 split | `meta.original_split` |

`group_id` 仍按 document/page 构建；`references` 完整保留。test 没有答案时使用空 `output.text` 和空 `references`，不伪造答案。

## 5. 如何运行

在项目根目录执行：

```bash
python -m src.convert \
  --config configs/datasets/docvqa.yaml \
  --clean-output
```

开发阶段可限制每个 split：

```bash
python -m src.convert \
  --config configs/datasets/docvqa.yaml \
  --limit 100 \
  --clean-output
```

运行环境需要具备 Python YAML 解析、`jsonschema` 和 `pyarrow`。

## 6. 验收结果

限量运行：train、validation、test 各读取 100 条，均为成功 100、失败 0。

全量运行结果：

| Split | 读取 | 成功 | 失败 |
|---|---:|---:|---:|
| train | 39,463 | 39,463 | 0 |
| validation | 5,349 | 5,349 | 0 |
| test | 5,188 | 5,188 | 0 |
| 合计 | 50,000 | 50,000 | 0 |

独立回归检查通过：

- 两个正式 Schema 的 Draft 2020-12 `check_schema` 通过；
- 50,000 条 Sample 全部通过 Schema；
- Config Schema 校验通过；
- 所有图片引用均为 `media/...`，且 12,756 个媒体文件全部可定位；
- `total_references = 50,000`，`unique_images = 12,756`；
- `supervised = 44,812`，`unsupervised = 5,188`；
- `output_chars` 只统计 44,812 条 supervised 样本；
- JSONL 不含原始 `datasets/` 路径；
- train/validation/test 数量保持不变，原始数据和 Schema 未修改。

因此，`processed/docvqa/` 携带其 `media/` 目录后可独立读取，不依赖原始 DocVQA 数据目录。
