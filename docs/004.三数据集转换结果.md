# DocVQA、ChartQA、MMTab 转换结果

## 1. 转换范围

本次结果基于现有统一 Converter 框架、Canonical Sample Schema 和 Dataset Config Schema，已完成：

- DocVQA → `processed/docvqa/`
- ChartQA → `processed/chartqa/`
- MMTab → `processed/mmtab/`

三套输出均采用 Canonical JSONL，并将实际使用的图片整理到各自的 `media/` 目录。

## 2. 当前 JSONL 规模

下表按当前 JSONL 文件逐行解析统计：

| 数据集 | train | validation | test | 总样本 | supervised | unsupervised | unique images |
|---|---:|---:|---:|---:|---:|---:|---:|
| DocVQA | 39,463 | 5,350 | 5,188 | 50,001 | 44,813 | 5,188 | 12,756 |
| ChartQA | 28,297 | 1,920 | 2,500 | 32,717 | 32,717 | 0 | 20,818 |
| MMTab | 232,879 | — | 49,726 | 282,605 | 282,605 | 0 | 106,068 |

说明：MMTab 原始数据没有官方 validation，因此未自行划分。

## 3. 任务与数据保留

| 数据集 | Canonical task | 任务/子集信息 |
|---|---|---|
| DocVQA | `document_visual_question_answering` | 保留 `question_types`、文档和页面元信息；test 无答案样本作为 unsupervised |
| ChartQA | `chart_question_answering` | `human` / `machine` 保存在 `meta.subset` |
| MMTab | `mmtab_*` | 12 个 Canonical task；`instruct` / `eval` 保存在 `meta.subset`；保留原始 `task_type` 和对话 history |

MMTab 输出格式分布为：`json` 219,791、`text` 56,481、`html` 6,333。

图片资源均使用 `storage: file` 和 `media/...` 相对路径，复制对应的 `processed/<dataset>/` 目录后不依赖原始数据集目录。

## 5. Schema 与资源校验

对当前全部 JSONL 样本执行 Draft 2020-12 Sample Schema 校验，并同时检查图片资源定位：

- DocVQA：50,001 / 50,001 PASS
- ChartQA：32,717 / 32,717 PASS
- MMTab：282,605 / 282,605 PASS
- 三份 Dataset Config：Schema PASS
- 两个正式 JSON Schema：`Draft202012Validator.check_schema` PASS

## 6. 统计文件说明

MMTab 的 `processed/mmtab/stats.json` 与当前 JSONL 一致。

检查时发现 DocVQA、ChartQA 的现有 `stats.json` 与当前 JSONL 存在小幅不同步：

- DocVQA：`stats.json` 为 50,000 条，当前 JSONL 为 50,001 条；
- ChartQA：`stats.json` 为 32,719 条，当前 JSONL 为 32,717 条。

这不影响当前 JSONL 的 Schema 和图片资源校验，但后续应重新生成这两份派生统计文件，使 `stats.json` 与 JSONL 保持一致。

## 7. 结论

三个 Converter 的核心转换、Canonical Schema 校验和图片迁移均已完成。DocVQA、ChartQA 的统计文件需要补做一次同步后，三套转换结果即可作为当前 M1 阶段的稳定产物。
