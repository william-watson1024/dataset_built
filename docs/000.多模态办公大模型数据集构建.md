
# 多模态办公大模型数据集构建路线

## 1. 总体目标

将不同来源、不同任务形式的数据集统一整理为一套可用于多模态办公大模型微调和评测的数据体系。

整体流程固定为：

```text
原始数据集
    ↓
统一数据格式
    ↓
各数据集转换
    ↓
数据校验与去重
    ↓
训练数据混合
    ↓
小规模训练验证
    ↓
正式训练
    ↓
统一评测
```

核心原则：

1. 统一数据格式，不强行统一任务。
2. 训练集与评测集严格隔离。
3. 保留每条数据的来源、任务类型和原始 ID。
4. 所有数据先转成内部统一格式，再适配具体训练框架。
5. 先小规模验证，再处理和训练完整数据。

---

## 2. M0：确定统一数据规范

先设计所有数据集共同使用的 Canonical Schema。

统一保存：

```text
id
source
split
task
language
images
messages
meta
```

其中：

- `source`：数据来自哪个数据集；
- `task`：属于什么办公任务；
- `images`：输入图片，可为空或多张；
- `messages`：统一为 user / assistant 对话；
- `meta`：保存原始 ID、答案类型、评测指标、group_id 等信息。

这一阶段只确定规范，不开始大规模转换。

验收标准：

> 所有数据集都能人工构造出一条符合统一格式的样例。

---

## 3. M1：搭建统一数据转换框架

建立统一的数据处理 Pipeline：

```text
读取原始数据
    ↓
转换为统一格式
    ↓
校验
    ↓
写入 JSONL
    ↓
生成统计信息
```

每个数据集只实现自己的 Converter。

统一提供：

```text
Converter
Validator
Writer
Statistics
```

目标是以后新增数据集时，只需要增加一个转换器，不修改整体框架。

---

## 4. M2：先处理基础视觉问答数据

第一批：

```text
ChartQA
DocVQA
```

主要验证：

```text
图片
+
问题
→
答案
```

这两个数据集结构简单，适合作为整个 Pipeline 的第一次验证。

处理完成后立即抽取约 5K～10K 数据进行一次 QLoRA 小规模训练。

目的不是追求效果，而是确认：

```text
图片读取正常
数据格式正确
image placeholder 正确
chat template 正确
loss 正常
模型可以正常推理
```

---

## 5. M3：加入表格理解能力

处理：

```text
MMTab-instruct
MMTab-pre（可选子集）
```

新增能力：

```text
表格图片理解
表格问答
表格推理
表格转写
多轮对话
```

MMTab-instruct 作为主要训练数据。

MMTab-pre 只作为可选的表格识别辅助数据，不必默认全部使用。

---

## 6. M4：加入金融表格推理

处理：

```text
FinQA
TAT-QA
```

新增一个统一的：

```text
TableRenderer
```

将结构化表格：

```text
JSON / List
```

渲染为：

```text
HTML
→
表格图片
```

最终训练形式：

```text
表格图片
+
财报文本
+
问题
→
答案 / 数值推理结果
```

这一阶段同时加入跨数据集去重。

重点检查：

```text
TAT-QA
↔
MMTab
```

防止相同表格或问题同时出现在不同数据集中。

---

## 7. M5：加入结构化办公信息抽取

处理：

```text
XFUND
Doc2EDAG
```

主要训练：

```text
文档 / 表单
→
结构化 JSON
```

例如：

```text
表单 → Key-Value
文档 → Entity
文档 → Relation
金融公告 → Event
```

这一阶段重点解决：

```text
统一 JSON 输出格式
结构化输出合法性校验
```

---

## 8. M6：加入长文档能力

处理：

```text
GovReport
```

用于训练：

```text
长文档
→
摘要
```

重点测试：

```text
上下文长度
token 截断
packing
显存占用
长文本训练效率
```

长文档可以根据实验结果单独作为一个训练阶段，不必强制与所有视觉数据同时训练。

---

## 9. M7：建立独立评测集

以下数据始终禁止进入训练：

```text
LongBench
LongBench-E
MMTab-eval
各数据集官方 test
```

统一建立：

```text
模型推理
    ↓
prediction.jsonl
    ↓
对应数据集 Evaluator
    ↓
metrics.json
```

各任务保留自己的指标，例如：

```text
DocVQA → ANLS
ChartQA → Relaxed Accuracy
FinQA → Execution Accuracy
TAT-QA → EM / F1
GovReport → ROUGE
LongBench → 各子任务指标
```

不强行将不同指标简单求平均。

---

## 10. M8：构建正式混合训练集

不直接把所有数据拼成一个巨大的 JSONL。

采用：

```text
多个独立 JSONL
+
sampling config
```

例如：

```text
DocVQA
ChartQA
MMTab
FinQA
TAT-QA
XFUND
Doc2EDAG
GovReport
ST-VQA
```

训练时动态控制各数据集采样比例。

这样以后可以方便进行：

```text
调整任务比例
增加 / 删除数据集
消融实验
不同训练阶段配置
```

---

## 11. M9：小规模完整训练验证

正式训练前，先构造一个约：

```text
5K～20K
```

样本的混合数据集。

完整验证：

```text
数据加载
→
训练
→
保存 checkpoint
→
加载模型
→
多任务推理
→
自动评测
```

只有这一整条链路正常，才进入正式训练。

---

## 12. M10：正式数据与模型训练

最终形成：

```text
高质量 Office-SFT 主训练集
+
可选表格/OCR预训练数据
+
完全隔离的 Benchmark Suite
```

再根据实验结果调整：

```text
数据规模
任务比例
训练轮数
上下文长度
LoRA / QLoRA 参数
```

---

## 最终路线

```text
M0 统一格式
 ↓
M1 转换框架
 ↓
M2 ChartQA + DocVQA
 ↓
首次小规模训练
 ↓
M3 MMTab
 ↓
M4 FinQA + TAT-QA
 ↓
M5 XFUND + Doc2EDAG
 ↓
M6 GovReport
 ↓
M7 独立评测体系
 ↓
M8 数据混合与采样
 ↓
M9 小规模完整验证
 ↓
M10 正式训练
```

一句话概括：

> 先统一格式并跑通最简单的图片问答，再逐步加入表格、金融推理、结构化抽取和长文档任务，最后完成数据混合、评测体系和正式训练。
